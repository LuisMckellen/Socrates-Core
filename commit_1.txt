Remove classifier confidence; trigger Groq fallback on classifier failure

The self-reported CONFIDENCE was uncalibrated: every few-row hardcoded
0.95 and replies only ever said 0.85-0.98, so the 0.7 threshold never
overrode a label. The only reachable use was the 0.0 set on client
error / unparseable reply / unknown label, which is what actually
triggered the Groq fallback.

- Drop CONFIDENCE from SYSTEM_PROMPT, every few-shot row, the parser,
  CONFIDENCE_THRESHOLD and the threshold branch.
- Fail-closed results now carry classifier_failed=True; the state
  machine falls back to Groq on that flag (or a raising classifier),
  and accepts a cloud result only if it did not fail too.
- "LABEL: partial" with a low number now yields partial: the stated
  label is no longer overridden by the number.
- Mock, UI label and docstrings updated. Golden prompt hash updated
  (001bfa92... -> ff5d42ee...); classifier prompt 740 -> 683 tokens.

Verified on Local CPU: six trace inputs x 3 reps, verdict / error_type /
error_source / matched_bank_id unchanged vs before.
