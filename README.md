# Socratic Core

An offline Socratic tutor: a two-tier question bank, a layered error
classifier and a hint pipeline. The model is Qwen3-4B-Instruct-2507. It has
three local runtimes behind one `generate()` interface:

- **NPU:** a Genie bundle compiled with Qualcomm AI Hub
  (`socratic_core/inference_client.py`). Reachable from the CLI only.
- **CPU fallback:** llama.cpp with a GGUF build of the same model
  (`socratic_core/local_client.py`). Fallback only.
- **Mock:** canned replies for development (`socratic_core/mock_client.py`).

An optional Groq cloud backend, which sends answers off-device, is off by
default (`socratic_core/cloud_client.py`, `ui/state.py:278`).

## Pipeline

Each Socratic answer goes through three classification layers, and the first
layer that decides wins (`socratic_core/state_machine.py:17-31`):

1. **Behavioural:** a give-up phrase, too few words, or an off-topic answer
   that also carries a disengagement token gives low_effort. Off-topic on its
   own falls through to the next layer
   (`socratic_core/classifier_behavioral.py:11-25`).
2. **key_terms, Case A and Case C:** if every key term is present, Case A
   runs a YES/NO verification call. If any key term is missing, Case C passes
   the answer to the LLM classifier (`socratic_core/state_machine.py:22-29`).
3. **LLM classifier:** emits one of correct, partial, wording_error or
   logic_error (`socratic_core/classifier_llm.py:100`).

There are two separate label spaces. The LLM labels above are mapped to
verdicts: correct to correct, partial to partial, and wording_error or
logic_error to wrong (`socratic_core/state_machine.py:135-140`). The
behavioural layer adds the fourth verdict, low_effort
(`socratic_core/state_machine.py:447-448`).

Hints are generated by the model and then checked in plain Python
(`socratic_core/hint_pipeline.py`). The checker rejects a hint that:

- names the answer or an accepted variant;
- contains the everyday-words correct example word for word (rule 3a);
- shares a 4-word run of content words with the answer (rule 3b);
- is longer than 25 words (`socratic_core/hint_pipeline.py:33,219`).

A rejected hint is retried once. If the retry fails too, the bank's fallback
hint is used.

## Question bank

`question_bank.json` has 32 questions (16 filter, 16 socratic),
35 misconceptions and 8 clusters (BASELINE.md:53). The format rules are
enforced when the bank loads (`socratic_core/question_bank.py:276-387`).

## Setup

- **CPU model:** `qwen3-4b-instruct-2507-q4_k_m.gguf` (Q4_K_M,
  2,497,281,120 bytes, BASELINE.md:54). Not committed because of its size
  (`.gitignore:3`).
- **NPU Genie bundle:** exported with Qualcomm AI Hub for Snapdragon X Elite,
  w4a16, QnnHtp, QAIRT 2.45.0
  (`evidence/npu_bundle_metadata.json:5,7,2151`,
  `evidence/npu_bundle_genie_config.json:28`). The client looks for it in a
  folder next to this repo, or at `SOCRATIC_MODEL_DIR` if set
  (`socratic_core/inference_client.py:44-45,73-76`). The bundle is not
  committed; its metadata and runtime config are copied into `evidence/`.
- **CPU model path:** `LocalCPUClient` defaults to a machine-specific WSL
  absolute path (`socratic_core/local_client.py:26`). The CLI has no flag to
  override it (`run_session.py:38-44`), so on a fresh clone you must change
  that default or pass `model_path=` to `LocalCPUClient`. The in-repo
  `models/` folder is gitignored and is not loaded by default.
- **NPU runtime:** needs `genie-t2t-run` from the QAIRT SDK, found via
  `SOCRATIC_GENIE_BIN`, `QNN_SDK_ROOT`/`QAIRT_SDK_ROOT` or `PATH`
  (`socratic_core/inference_client.py:46-48,205-226`).
- **NPU hardware:** the NPU path targets the Snapdragon X Elite NPU via
  Qualcomm AI Hub. No local Snapdragon hardware is available to the author.
  NPU latency on the pipeline has not been measured end to end (BASELINE.md:
  "No NPU run").

## Usage

CLI:

```
python run_session.py                  # mock client
python run_session.py --client local   # CPU fallback (llama.cpp)
python run_session.py --client npu     # NPU via Genie
```

The `--client` choices are mock, local and npu (`run_session.py:44`).

UI:

```
pip install streamlit
streamlit run app.py
```

The sidebar offers three backends: Mock, Local CPU and Groq
(`ui/state.py:32-36`). It starts on Mock (`ui/state.py:278`), and Groq needs
an explicit switch. The NPU is not offered in the UI (`ui/state.py:36,88`).
The sidebar also filters clusters and resets the session. "🔍 Pipeline
internals" shows which layer resolved the last turn and how long each model
call took (`ui/debug_panel.py:33-44`).

## Eval

```
python eval/run_eval.py eval/socratic_eval_input.jsonl --repo .
```

Verdict accuracy of 56/60 (93.3%) on 60 synthetic rows, all from a single
question (s_cell_theory_L1), scored on the CPU backend (BASELINE.md;
`eval/run_eval.py:26,55`).

Matching answers to bank misconceptions is scored separately:

- **Matched accuracy:** 19/21 on rows with a labelled match (BASELINE.md).
- **False matches:** on the 39 rows with no labelled match, 17/39 were
  falsely matched, counting only rows that are not correct answers matched to
  natural_correct (BASELINE.md).
- **Off-topic rows:** all 8 off-topic and self-contradictory rows were forced
  to ct_spontaneous_generation (`eval/socratic_eval_results.jsonl:46-53`).

CPU fallback latency per answer: p50 7167 ms, p95 7388 ms (BASELINE.md).

## Failure modes

- **NPU reload per call:** each NPU `generate()` call starts a fresh
  `genie-t2t-run` process (`socratic_core/inference_client.py:301,309,340-346`).
  The four context binaries total 3,166,048,256 bytes (BASELINE.md:55;
  `evidence/npu_bundle_genie_config.json:48-53` lists them). `use-mmap` is
  enabled (`evidence/npu_bundle_genie_config.json:31`), so the OS page cache
  may absorb repeat loads. This is unmeasured.
- **NPU output length is not bounded:** `_apply_max_tokens`
  (`socratic_core/inference_client.py:410-420`) does nothing, so the client
  does not limit how much the NPU generates. The 64-token hint cap
  (`socratic_core/hint_pipeline.py:34,174`) is passed to every backend, but
  only llama.cpp and Groq enforce it (`socratic_core/local_client.py:89`,
  `socratic_core/cloud_client.py:116`). The prompt asks for fewer than 25
  words (`socratic_core/hint_pipeline.py:42`), and the validator enforces
  that after generation (`socratic_core/hint_pipeline.py:219`).
- **False matches:** misconception matching falsely matches 17/39 rows with
  no labelled match (see Eval).
- **Either/or leaks:** after rule 3c was removed, only a prompt instruction
  guards against a hint that offers the correct mechanism as one side of an
  either/or (`socratic_core/hint_pipeline.py:68-69`, CORRECTIONS.md #10).
