# Socratic Core

A diagnostic layer for a Socratic tutor. It grades one free-text answer,
names the misconception it matches, and responds with a guiding question
rather than the answer. The model is Qwen3-4B-Instruct-2507, targeted at
the Snapdragon X Elite NPU.

## Architecture

- **The bank holds the knowledge.** `question_bank.json` stores every
  question with its accepted answers, key terms, known misconceptions and a
  hand-written hint. Correct answers and reveals come from the bank, never
  from the model (`socratic_core/question_bank.py`,
  `socratic_core/state_machine.py:732-739`).
- **The model is swappable.** Every backend exposes the same
  `generate(prompt, max_tokens)` call:
  - **NPU:** a Genie bundle from Qualcomm AI Hub, run with `genie-t2t-run`
    (`socratic_core/inference_client.py`).
  - **Local CPU:** llama.cpp with a Q4_K_M GGUF of the same model
    (`socratic_core/local_client.py`).
  - **Groq:** Qwen3-32B in the cloud. Sends answers off-device
    (`socratic_core/cloud_client.py`).
  - **Mock:** canned replies for development and tests
    (`socratic_core/mock_client.py`).
- **Routing is layered.** Behavioural rules run first and catch
  low-effort answers with no model call. Every other answer reaches the
  model: if every key term is present (allowing synonyms), Case A asks it
  for a one-word YES/NO verification; if any key term is missing, Case C
  runs the full classifier. On the eval, the model decided 54 of 60 rows
  (`socratic_core/state_machine.py:17-31`; `error_source` in
  `eval/socratic_eval_results.jsonl`).

## Session flow

Questions come in two tiers (`socratic_core/question_bank.py:148-150`).

- **Filter:** a one-fact probe, graded by exact match after normalisation,
  with no model call (`socratic_core/state_machine.py:355-393`). A miss lowers
  the cluster's mastery. Below 0.40 the session inserts a Socratic question
  from the same cluster, at level 1 or 2 depending on mastery
  (`socratic_core/mastery.py:15-26`, `socratic_core/escalation.py:30-46`).
- **Socratic:** an explain-the-mechanism question that runs the full pipeline
  below. After 3 wrong or partial attempts the answer is revealed from the
  bank (`socratic_core/state_machine.py:131,497-502`).

A session walks the filter questions; Socratic questions are reached only by
escalation (`socratic_core/state_machine.py:297-302`).

## Pipeline

Each Socratic answer goes through three classification layers, and the first
layer that decides wins (`socratic_core/state_machine.py:17-31`):

1. **Behavioural:** a give-up phrase, too few words, or an off-topic answer
   that also carries a disengagement token gives low_effort. Off-topic on its
   own goes on to the next layer
   (`socratic_core/classifier_behavioral.py:11-25`).
2. **Key terms, Case A and Case C:** if every key term is present (allowing
   synonyms), Case A runs a one-word YES/NO verification call. If any key term
   is missing, Case C passes the answer to the LLM classifier
   (`socratic_core/state_machine.py:22-29`).
3. **LLM classifier:** emits one of correct, partial, wording_error or
   logic_error (`socratic_core/classifier_llm.py:100`). Alongside the label,
   the classifier names the bank misconception the answer most closely
   matches, or `none`. The match does not affect the label; it drives the
   targeted hint prompt and the session log
   (`socratic_core/classifier_llm.py:68-70`,
   `socratic_core/hint_pipeline.py:114-115`,
   `socratic_core/state_machine.py:811`).

There are two label spaces. The LLM labels map to verdicts: correct to
correct, partial to partial, and wording_error or logic_error to wrong
(`socratic_core/state_machine.py:135-140`). The behavioural layer supplies the
fourth verdict, low_effort (`socratic_core/state_machine.py:447-448`).

Hints are generated by the model and checked in plain Python
(`socratic_core/hint_pipeline.py:195-225`). The checker rejects a hint that:

- is empty;
- names the correct answer or an accepted variant;
- contains the everyday-words correct example word for word;
- shares a run of 4 content words with the answer, a variant or the
  everyday-words example;
- is longer than 25 words, or does not end in a single `?`.

A rejected hint is regenerated once. For a partial answer the hint must also
name a missing key term, and if the model will not, a template names it
(`socratic_core/hint_pipeline.py:263-271`). Otherwise the bank's hand-written
hint is used (`socratic_core/hint_pipeline.py:272`). A client error or an
empty reply goes straight to that fallback
(`socratic_core/hint_pipeline.py:253-258`).

## Question bank

`question_bank.json` has 32 questions (16 filter, 16 socratic), 35
misconceptions and 8 clusters (RESULTS.md, Assets). The format rules are
enforced when the bank loads (`socratic_core/question_bank.py:276-387`).

## Setup

Python 3.11.

```
pip install -r requirements.txt
```

`requirements.txt` pins streamlit, llama-cpp-python, openai (the SDK the Groq
backend uses) and pytest. On Windows, pip builds llama-cpp-python from source
and needs a C/C++ toolchain. The Mock backend and the UI need only streamlit.

- **CPU model:** a Q4_K_M GGUF of Qwen3-4B-Instruct-2507,
  `qwen3-4b-instruct-2507-q4_k_m.gguf` (2,497,281,120 bytes). It is not in the
  repo (`.gitignore:3`). `LocalCPUClient` defaults to a machine-specific path
  (`socratic_core/local_client.py:26`) and the CLI has no flag for it. Point
  that default at `models/qwen3-4b-instruct-2507-q4_k_m.gguf` (relative paths
  resolve against the repo root, `socratic_core/local_client.py:36-38`), or
  pass `model_path=` to `LocalCPUClient`.
- **NPU bundle:** Qwen3-4B-Instruct-2507 exported from Qualcomm AI Hub for
  Snapdragon X Elite (w4a16, Genie runtime; see `evidence/README.md`). Put
  the folder `qwen3_4b_instruct_2507-genie-w4a16-qualcomm_snapdragon_x_elite`
  next to this repo, or set `SOCRATIC_MODEL_DIR`
  (`socratic_core/inference_client.py:44-45,73-76`).
- **NPU runtime:** `genie-t2t-run` from the QAIRT SDK, found via
  `SOCRATIC_GENIE_BIN`, `QNN_SDK_ROOT`/`QAIRT_SDK_ROOT` or `PATH`
  (`socratic_core/inference_client.py:46-48,205-226`). Per-call timeout:
  `SOCRATIC_GENIE_TIMEOUT_S`, default 180 s
  (`socratic_core/inference_client.py:49`).
- **Groq (optional):** set `GROQ_API_KEY` in the environment or in
  `.streamlit/secrets.toml` (`socratic_core/cloud_client.py:29,56-58`).
- **Other settings:** `SOCRATIC_QUESTION_BANK` points at a different bank
  (`socratic_core/question_bank.py:239-243`); `SOCRATIC_SESSIONS_DIR` moves
  the session logs (`socratic_core/state_machine.py:225-229`).

## Usage

CLI:

```
python run_session.py                  # mock client
python run_session.py --client local   # Local CPU (llama.cpp)
python run_session.py --client npu     # NPU via Genie
```

The `--client` choices are mock, local and npu (`run_session.py:44`). The CLI
starts on the first question in the bank unless `--question-id` is given
(`run_session.py:57`).

UI:

```
streamlit run app.py
```

The sidebar offers three backends: Mock, Local CPU and Groq
(`ui/state.py:32-36`). It starts on Mock (`ui/state.py:278`). The NPU is not
offered in the UI (`ui/state.py:88`). Behind Local CPU, the sidebar can also
enable Groq as a fallback when the local classifier fails
(`ui/sidebar.py:69-77`, `ui/state.py:105-113`). "🔍 Pipeline internals" shows
which layer resolved the last turn and the classify and hint call times
(`ui/debug_panel.py:33-44`).

Every session is written to `sessions/<session-id>.json` after each turn,
including the student's answers (`socratic_core/state_machine.py:98-100,533-542`).

## Results

```
python eval/run_eval.py eval/socratic_eval_input.jsonl --repo . --out results.jsonl
```

The eval needs llama-cpp-python and the CPU model. Without `--out` it writes
`eval/socratic_eval_input.results.jsonl` (`eval/run_eval.py:52`).

60 synthetic rows, all on one question (s_cell_theory_L1), scored on the
Local CPU backend (RESULTS.md, Eval; `eval/run_eval.py:26,55`):

- **Verdict accuracy:** 56/60 (93.3%).
- **Matched accuracy:** 19/21 on rows with a non-empty `expected_matched`.
- **Abstain success:** 12/39 on rows with no labelled match.
- **False matches:** 27/39 on those rows; 17/39 excluding correct answers
  matched to natural_correct.
- **Off-topic and self-contradictory rows:** all 8 are matched to
  ct_spontaneous_generation (`eval/socratic_eval_results.jsonl:46-53`).
- **Latency per answer on Local CPU:** p50 7167 ms, p95 7388 ms.

## Failure modes

- **Mock is the default backend.** The UI starts on Mock (`ui/state.py:278`)
  and so does the CLI (`run_session.py:44`). Mock replies are canned text,
  not grading (`socratic_core/mock_client.py`).
- **The eval is narrow.** 60 synthetic rows, one question, Local CPU only
  (RESULTS.md, Eval).
- **The NPU path is untested and unmeasured.** The one recorded NPU session
  (`evidence/npu_run.json`) never reached the model: every classifier and hint
  call returned a client error (`evidence/npu_run.json:24,30,55-57`), so the
  session ran on bank fallback hints. `socratic_core/inference_client.py` has
  no test coverage: `load_bundle`, `find_genie_binary`, `_parse_output` and `_parse_profile`
  are never exercised.
- **NPU reload per call:** each NPU `generate()` call starts a new
  `genie-t2t-run` process (`socratic_core/inference_client.py:301,309,340-346`)
  that loads 3,166,048,256 bytes of context binaries (RESULTS.md, Assets).
  `use-mmap` is on (`evidence/npu_bundle_genie_config.json:31`), so the OS
  page cache may absorb repeat loads. This is unmeasured.
- **NPU `max_tokens` is a no-op:** `_apply_max_tokens`
  (`socratic_core/inference_client.py:410-420`) returns the config unchanged,
  so nothing limits how much the NPU generates. Only llama.cpp and Groq
  enforce the cap (`socratic_core/local_client.py:89`,
  `socratic_core/cloud_client.py:116`). The hint prompt asks for fewer than 25
  words (`socratic_core/hint_pipeline.py:42`) and the checker enforces it
  after generation.
- **NPU sampling differs:** the bundle samples at temperature 0.8
  (`evidence/npu_bundle_genie_config.json:15`); Local CPU and Groq run at 0.2
  (`socratic_core/local_client.py:28`, `socratic_core/cloud_client.py:34`).
  NPU output is not directly comparable to the eval.
- **The hint checker covers direct leaks only.** It is string matching: a
  synonym-for-synonym paraphrase of the answer passes
  (`socratic_core/hint_pipeline.py:22-23`). A hint that offers the correct
  mechanism as one side of an either/or is guarded only by the prompt
  instruction "Do not offer alternatives. Do not present two options"
  (`socratic_core/hint_pipeline.py:68-69`).
- **False matches:** misconception matching falsely matches 17/39 rows with
  no labelled match (see Results).
- **The eval's default repo path is WSL-only:** the default `--repo` is a
  WSL absolute path (`eval/run_eval.py:3,25`). On Windows, pass `--repo .`
  explicitly.
- **The CPU model path is machine-specific** (`socratic_core/local_client.py:26`;
  see Setup).
- **Backend load errors are silent in the UI.** A Local CPU backend with no
  model or no llama-cpp-python does not raise
  (`socratic_core/local_client.py:45-53`). Every classifier call then fails
  closed to logic_error and every hint is the bank's fallback, with no error
  shown.
- **Prompts assume biology.** The classifier, verify and noise-tolerance
  texts say "biological" (`socratic_core/classifier_llm.py:121,357`,
  `socratic_core/noise.py:18`), while the genetic_algorithms cluster covers
  GA implementation.
